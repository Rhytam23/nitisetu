## 1. Confirmed Implemented Data Models

### 1.1 Farmer Profile Model (`Farmer.js`) `[IMPLEMENTED]`
- **Collection Name**: `farmers` (Database: `niti-setu`)
- **Schema Location**: [backend/models/Farmer.js](file:///e:/nitisetu/backend/models/Farmer.js)
- **Options**: `{ timestamps: true, strict: false }`

| Field Name | Type | Required | Default | Constraint / Index | Description |
|---|---|---|---|---|---|
| `_id` | ObjectId | System | Auto | Primary Key | MongoDB Unique ID |
| `name` | String | Yes | None | Trimmed, min length 2 | Full name of farmer |
| `state` | String | Yes | None | Trimmed | State of residence |
| `land_acres` | Number | No | 0 | Min: 0 | Total cultivable landholding in acres |
| `crop` | String | No | `""` | Trimmed | Primary crop cultivated (e.g. Wheat) |
| `age` | Number | No | `null` | Integer 18–100 | Age of farmer |
| `phone` | String | No | `undefined` | Unique, Sparse | 10-digit mobile number |
| `aadhaar` | String | No | `undefined` | Unique, Sparse | 12-digit Aadhaar number |
| `createdAt` | Date | System | Auto | Index | Creation timestamp |
| `updatedAt` | Date | System | Auto | None | Last update timestamp |

**Privacy & Security Considerations**:
- `phone` and `aadhaar` fields use **sparse unique indexes** so that farmers can omit sensitive identity fields during casual consultations without triggering duplicate null constraint errors.

### 1.2 Scheme Document Vector Model `[IN PROGRESS]`
- **Collection Name**: `scheme_documents` (Database: `niti-setu`)
- **Atlas Index Name**: `vector_index`
- **Vector Spec**: 768 dimensions, Cosine similarity over `embedding`

| Field Name | Type | Required | Description |
|---|---|---|---|
| `_id` | ObjectId | System | Primary Key |
| `text` | String | Yes | 1,000-character split text chunk from official PDF |
| `embedding` | Array<Number> | Yes | 768-dimensional float vector generated by Gemini |
| `metadata.source` | String | Yes | Original PDF filename (e.g. `PM-KISAN.pdf`) |
| `metadata.scheme_name` | String | Yes | Name of scheme (e.g. `PM-KISAN`) |
| `metadata.type` | String | Yes | Document type (`eligibility_guidelines`) |

## 2. Proposed Data Models (Planned Architecture)

### 2.1 Scheme Metadata Model `[PROPOSED]`
*Planned model for dynamic scheme administration.*

| Field Name | Type | Required | Description |
|---|---|---|---|
| `scheme_id` | String | Yes | Unique identifier (e.g. `pm-kisan`) |
| `title` | String | Yes | Full scheme title |
| `ministry` | String | Yes | Government ministry / department |
| `benefit_amount` | Number | No | Financial benefit value in INR |
| `max_land_acres` | Number | No | Maximum land limit eligibility cutoff |
| `age_min` | Number | No | Minimum eligible age |
| `age_max` | Number | No | Maximum eligible age |

### 2.2 Application Record Model `[PROPOSED]`
*Planned model for tracking formal scheme applications.*

| Field Name | Type | Required | Description |
|---|---|---|---|
| `application_id` | ObjectId | System | Primary key |
| `farmer_id` | ObjectId | Yes | Reference to `Farmer._id` |
| `scheme_id` | String | Yes | Target scheme code |
| `status` | String | Yes | `Draft` \| `Submitted` \| `Under Review` \| `Approved` |
| `submitted_at` | Date | No | Submission timestamp |
